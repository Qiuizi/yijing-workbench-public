该决议构成对 [原发布标准](learning-approval-policy.md) 所要求先完成所有逐条校勘后才批准的**一次明示例外**。必须以可核对的变更、明确的证据范围和真实的 UI 保护测试为前提；不通过编造、删除旧稿或重写历史来假装已完成校勘。

## 技术发布及版本范围

- 本次只将**正式公开资格**在源码层面从原有 4/64 调整到 64/64；现有 `reviewedGuide(id)` 的**双重门控逻辑不能删除**：只有 `learning_guides.json` 为 `reviewed` 且 `learning_approvals.json` 中存在有效批准记录才可展示，缺任一条件依然隐藏。
- 01–04 既有批准不覆盖、不改日期/历史 PR；05–64 依照这次 PR 的链接和真实批准日期单独记录。
- 不改变 `backend/data/hexagrams.json`、古籍来源修订号、原始现代解释内容、AI 密钥或 SQLite 历史。
- **重要版本区分**：已经发布的 **v3.3.0 Windows NSIS 安装包**是基于更早的 `e5f613c` 生成，内置的仍是**01–04 可见、05–64 草稿**。此 PR 合并只更新 GitHub 源码；要让最终用户桌面应用看到 64 篇导读，必须另行打包并发布后续版本。不得把已经发布的旧安装包说成包含新批准。
- 后续文献发现错误可继续按新的 PR 修订，必要时可撤销具体卦的 `reviewed` 与批准台账条目；不能回写旧审核历史的真实性。

**结论：维护者批准的“editorial reviewed”生效范围为源码与未来新构建；“philological text-audited（逐处古注版本学完成）”仍不宣称全完成。**
