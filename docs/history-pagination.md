# 历史记录搜索与分页

`GET /api/history` 保留 `{ "items": [...], "total": N }` 响应结构。

| 参数 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `q` | 空字符串 | 占问内容的字面子串，去掉两端空白，最多 500 字符；`%`、`_`、反斜杠不是通配符。采用 SQLite LIKE 的匹配规则，ASCII 不区分大小写，中文按字匹配。 |
| `ai_filter` | `all` | `all`、`with-ai`、`without-ai`；按是否存在 AI 会话筛选，延续原有标记语义，不读取消息。 |
| `limit` | `20` | 整数，1–100。 |
| `offset` | `0` | 整数，0–1,000,000。超出匹配总数时返回空 items，total 仍为准确匹配数。 |

例如：`/api/history?q=阅读&ai_filter=with-ai&limit=20&offset=20` 返回匹配结果的第二页。
非法参数返回 HTTP 422。结果保持 `created_at DESC, id DESC` 的稳定顺序；列表和总数在同一只读事务中获取。

**契约调整**：旧版无参数调用一次返回全部记录；现在无参数只返回前 20 条，`total` 仍表示全部匹配记录数。仓库内调用方和测试已同步，外部调用方应使用 limit/offset 翻页。多次翻页之间若发生新增或删除，offset 分页不承诺跨请求快照。

前端每页 20 条，搜索输入防抖 250ms；关键词/AI 筛选变化回到第一页。请求序号在条件改变时立即失效，旧成功/失败响应均不会覆盖新状态。打开记录后保留查询条件与页码，返回时刷新；删除后重载当前页，末页为空时回到最后一个有效页。本轮不访问真实用户数据库，不增加数据迁移或索引。

## 可复现合成基准

在仓库根目录执行 `.venv/bin/python -m scripts.benchmark_history`。脚本只创建临时 SQLite，比较基于 main `d839747` 列表逻辑复现的旧接口与当前接口；二者使用同一 TestClient 和响应模型。测试后清理临时库。

2026-10-16 Cloud Linux / Python 3.12.10；1,000 条合成记录、334 个 AI 会话；每种情况预热 1 次、测量 7 次。以下为完整请求耗时，含 TestClient、SQL 跟踪及 JSON 响应序列化：

| 请求 | 返回条数 / 匹配总数 | SELECT / 连接数 | 响应字节 | 中位耗时 ms | 最小–最大 ms |
| --- | --- | --- | --- | --- | --- |
| 旧接口，无条件全量 | 1,000 / 1,000 | 1,001 / 1,001 | 201,476 | 384.860 | 347.256–391.736 |
| 新接口，默认第一页 | 20 / 1,000 | 2 / 1 | 4,059 | 3.965 | 2.430–5.271 |
| 新接口，中文搜索 + 有 AI | 20 / 334 | 2 / 1 | 4,044 | 4.015 | 3.718–5.281 |

默认请求返回的数据量已经改变，因此不能把耗时比解释为等量数据吞吐提升，也不代表 Windows 实机表现。查询次数的下降来自取消逐条连接及会话加载；响应体缩小来自分页。包含子串和 AI 筛选的准确总数仍需扫描候选记录，不宣称任意规模下恒定耗时。

EXPLAIN QUERY PLAN 显示排序使用已有 `idx_divinations_created_at`，EXISTS 使用已有覆盖索引 `idx_ai_sessions_divination`。未新增索引或全文搜索系统。

Windows 历史页面 GUI、中文输入快速搜索、筛选/翻页、删除末页回退、打开并返回及 Markdown 保存对话框/真实落盘均为 NOT_TESTED，需本地手工验收。
