## 一、环境失败的根因与处理

接手时的三个"失败"都不是源码问题，记录如下。

### 1. 仓库根目录 `npm ci` 失败

根因：**仓库根目录没有 `package.json` / `package-lock.json`**。这是一个 Python + Tauri 仓库，Node 依赖只存在于 `frontend/` 与 `website/` 两个子项目。`npm ci` 在无 package.json 的目录必然以 `ENOENT` 退出，与源码质量无关。

处理：改为按子项目执行，全部通过。

```
npm --prefix frontend run typecheck
npm --prefix frontend run test
npm --prefix frontend run build
npm --prefix website  run typecheck
npm --prefix website  run build
```

### 2. 基线验证"仍然失败"——实为 Git Bash 的路径转换

根因：在 Git Bash（MSYS2）下，`--base /yijing-workbench-public/` 这个以斜杠开头的参数被 MSYS 当作 Windows 路径自动转换：

```
链接检查 · dist: D:\Qiuizi\project\yijing\website\dist · base: /D:/Users/123/AppData/Local/Programs/WorkBuddy/resources/vendor/PortableGit/yijing-workbench-public/
HTML 文件: 2 个；内部链接: 6（缺失 4）
汇总: ✗ 存在 4 个失败
```

`base` 被改成了 Git 安装目录，于是所有 `/yijing-workbench-public/assets/*` 都判定缺失。这不是站点或 `check-links.mjs` 的缺陷。

处理：关掉 MSYS 路径转换后同一份产物通过：

```bash
MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*" \
  node website/scripts/check-links.mjs --dir website/dist --base /yijing-workbench-public/
# HTML 文件: 2 个；内部链接: 6（缺失 0）… 汇总: ✓ 通过
```

在 PowerShell 7（本仓库默认 shell）下不存在该问题；这条只影响 Git Bash 复现方式。

### 3. 工作分支落后 origin/main 六个提交

根因：本地分支 `fix/frontend-ui-audit` 停在 `5b95fb8`，而 `origin/main` 已到 `4e6a48c`，其中 `4e6a48c fix(site): publish v3.3.1 with release-matched checksum`（#38）已经修掉了我最初在旧基线上看到的两类问题：

- 站点固定数据仍写 v3.3.0（EXE 名 / 字节数 / SHA-256 全部是 3.3.0 的）；
- 下载卡把 **动态取到的 tag/文件名/大小** 与 **静态的旧 SHA-256** 混着渲染。

在旧基线上这会导致线上出现"v3.3.1 的包名 + v3.3.0 的哈希"——正是任务禁止的错配。**该错配在 main 上已修复**，本次不重复修改，只做了基线与核对：

- `git merge --ff-only origin/main` 前移工作分支；
- 复核 `DownloadSection.vue` 现在把 `tag`、`exe.name`、`exe.size`、`exe.browser_download_url`、`digest` 全部绑定到同一次 GitHub API 响应，校验失败即整体回退到固定数据；

- 桌面端把 `.app-main` 的左右 padding 换成 `.workbench` 的 `width: calc(100% - var(--shell-pad)*2)` + `margin-inline:auto`。任何**不在 `.workbench` 内**的 `.app-main` 直接子元素都会失去原有留白——目前只有 `.topbar`、`.app-footer`、`LearningHeader`，三者都已显式处理；后续若新增直接子元素需注意。
- 官网 `.features__grid` 从 `auto-fill` 改为 12 栏 + 位置选择器，**依赖卡片数量为 7**（中英词典均为 7 且受 `Dictionary` 类型约束）。增删卡片需同步调整 `:nth-child`。
- 官网 8 栏图鉴依赖 64 卦全量显示；筛选到「上经 30 / 下经 34」时最后一行仍然是自然的未满行（这是筛选语义，不是布局缺陷）。
- `--shell-pad` 是新增的自定义属性，若其它分支也在改顶栏宽度需要留意覆盖顺序（`redesign.css` 在 `style.css` 之后加载）。
