# 六十四卦编辑导读上线门槛（从 V1 开始）

本文件定义**批准导读进入正式阅读页**的证据标准。内容初稿、GitHub PR 已合并、自动化测试通过，均不等于文献校勘或发布批准。

## 现有记录与权限

- `frontend/src/data/learning_guides.json`：包含全部 64 篇及 384 条逐爻说明；字段 `review_status` 可以是 `draft` 或 `reviewed`。
- `frontend/src/data/learning_approvals.json`：独立发布批准台账。正式选择器 `reviewedGuide` **同时检查台账和状态**，缺一不可。
- 01–04 卦最早由 PR #8 审核批准。**2026-10-24 起维护者明确对 05–64 共 60 卦作出编辑公开批准（PR #35）**：台账记录对应批准 PR、日期和审稿文档，全部 64 卦在该源码及后续构建可展示。批准的**公开许可**不等于全部完成古籍版本学逐字校勘。此前 05–64 为 `draft` 的状态是历史事实，不应被改写。

## 两种“来源验证”不能混为一谈

仓库 `backend/data/README.md` 已记录：2026-09-24 曾用维基文库 MediaWiki API 按 64 个固定修订号核对 **64 卦卦辞、384 条爻辞及乾坤特殊爻辞，共 450 项经典来源文本**。这是项目现有的、**有日期的来源核对记录**，不应笼统写成“固定 oldid 从未验证”。

但该历史记录不等于我们此次重新从 API 取得全部页面和扫描影像作独立复核，更不等于现代导读的王弼、孔颖达、朱熹训释经过逐条学术核验。**已记录经典来源核对 ≠ 新一轮独立版本校勘 ≠ 现代导读发布批准**。遇到《大畜》等当前网站文本与旧版差异，原本的经典 JSON 不可自动覆盖。

目前额外提供 `scripts/prepare_learning_review.py`，可生成 64 份 Markdown 审稿包，把每卦原文、六爻说明、固定修订和古注入口并列；该导出不改动审定状态。示例运行：

```bash
python scripts/prepare_learning_review.py --output review-packets
```

每份文件名为 `hexagram-001.md` 等 ASCII 名称，可在 Obsidian 查看；也可从 CI 中取回 `yijing-64-hexagram-review-markdown` Artifact。勾选审核清单本身不等于批准，还须按下述规定操作台账和 PR。

## 每一卦的必要校读

1. **原始内容定位**：确认文王卦序、本卦、卦辞、六爻、上下卦，以及本项目固定的 `source_url` 与 `source_revision_id`；不因外部页面版本变化覆盖经典数据。
2. **古注逐条追溯**：卦辞和六个爻位逐个对照 `《周易正义》` 对应段落，注明经文、王弼注、孔颖达疏之间的说法归属；对含实质主张的 `《周易本义》` 解释做对应位置校对。
3. **异文与解释分歧**：记录影响理解的字形、断句、训诂和传统观点差别，区分未核对/存疑/已核对；禁止把访问过卷页面等同于已逐爻校核。
4. **现代编辑内容**：重新检查一句话、200–350 字核心导读、六条 60–120 字逐爻说明是否各自具体、准确、有上下文；传统礼制、等级、战争、婚姻和疾病不得直接转换为现代现实命令或确定预言。
5. **审稿文档同步**：将证据、校勘结果和 JSON 修订反映到对应 `docs/learning-guides-review-*.md` 中。原则上缺少完整证据时保留 `draft`；若维护者**明示批准编辑公开并接受未经完成学术校勘的风险**，需以单独有日期的决议文档和 PR 明确记载例外，不得回填虚假文献核读记录。
6. **批准登记与测试**：通常在逐卦完整校读且取得维护者逐卦确认后，同步修改 `review_status` 与批准台账；2026-10-24 的 05–64 卦按维护者**明确批量编辑批准的特例**处理，依据 [决议/逐卦材料清单](learning-guides-review-05-64.md) 记录内容范围及尚未完成的核读。每条台账仍必须包含 `hexagram_id`、`approval_pr`、`audit_document`、`approved_on`。修改需通过 Vitest、类型检查、构建及阅读页门控回归。

## 严格区分的三个完成状态

| 状态 | 衡量什么 | 当前范围 |
| --- | --- | --- |
| drafted | 现代导读和逐爻说明已写入仓库 | 64/64 |
| text-audited | 已实际逐卦/逐爻追溯经文及关键古注、记录分歧 | 尚未完成 60 卦的全部核读 |
| approved（编辑公开许可） | 审核记录和发布标志双门槛生效，允许在**本提交及之后的新构建**中展示 | 01–64（含 05–64 的维护者明示例外） |

**当前发布原则及例外**：默认没有证据时保留原文并将现代稿隐藏；2026-10-24 维护者另行明确批准 05–64 整批现代编辑内容公开（见 [正式决议](learning-guides-review-05-64.md)），并接受未完成全量古注影印校勘的剩余风险。**`reviewed` 的运行时语义是编辑发布获准，不表示 `text-audited` 已全部完成。** 

**构建生效范围**：先前正式发布的 v3.3.0 Windows 安装包仍由旧源码生成，仅展示 01–04 卦；仓库 main 更改不可能反向更新旧安装包，必须重新构建/发布后续桌面版本才能让终端用户看到 64 篇。

## 版本验收不是学术审核

`windows-rc.yml` 的 Windows CI 可证明候选源码在托管 Windows 环境下通过自动化测试、PyInstaller/Tauri/NSIS 构建并生成 SHA-256；这**不证明**真实用户机器上的安装、升级、WebView2、DPAPI 和界面手工体验。发布正式桌面 Release 之前，还需按 `docs/windows-rc-3.3.0-acceptance.md` 留存验收记录。
