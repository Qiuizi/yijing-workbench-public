# 易经起卦工作台 v3.3.0 更新说明

**发布候选草稿，尚未发布。** 当前源码版本为 3.3.0；正式下载入口仍为 [v3.2.2 Release](https://github.com/Qiuizi/yijing-workbench-public/releases/tag/v3.2.2)。本轮不生成安装包、Tag 或 GitHub Release。

## 本次更新

- **单条 Markdown 导出**：在起卦结果、解卦或六爻排盘页面点击“导出 Markdown”，即可保存 UTF-8 `.md` 文件，供 Obsidian、Markdown 阅读器或个人存档使用。包含占问、原始时间/方式、本卦/动爻/之卦、实际展示的原文与来源、传统取辞，以及已有的已保存排盘。不会重新起卦或计算排盘；取消保存不报错，失败会给出提示。示例见 [合成导出示例](markdown-export-example.md)。
- **历史记录搜索、筛选和分页**：保留占问关键词搜索及“全部 / 有 AI / 无 AI”筛选，改为服务端查询，每页 20 条；支持上一页、下一页和匹配总数显示。更改搜索或筛选时回到第一页，快速输入时忽略旧请求结果；删除记录后刷新，末页为空时回退。打开历史详情并返回后保留搜索条件和页码。
- **“关于”页修复**：正确显示应用版本、MIT 许可范围与完整 LICENSE 正文，区分古籍来源许可和第三方组件许可证。许可证正文内置于前端资源，可离线查看，不依赖启动时所在目录。
- **64 卦学习图鉴与原文阅读**：按文王序浏览 64 卦、检索与逐卦阅读卦辞、爻辞及乾坤特殊爻。64 卦现代导读草稿已齐备，但**正式批准并可见的只有 01–04 卦**；05–64 卦依然只显示经典原文和“导读整理中”。新增加入了批准台账与状态双门槛，禁止仅改状态字段就公开未审内容。

铜钱/手动起卦、传统取辞与卦辞爻辞阅读、六爻纳甲排盘及可选 DeepSeek 辅助解读继续保留。业务逻辑稳定核心标识仍为 V3.1.4，不代表当前应用版本。

## 已知限制

- Markdown 导出只包含当前一条起卦记录及其已有排盘，不包含 AI 会话、API Key 或内部配置；无已保存排盘时明确标注，不自动补算。
- DeepSeek 为用户自行配置并主动调用的可选联网功能；导出、历史搜索和分页不会自动调用 AI。
- 历史关键词搜索为字面子串，不支持全文语义搜索；有/无 AI 筛选依据是否存在 AI 会话，不保证会话中已有完整回答。
- 历史接口无参数调用现在只返回前 20 条，`total` 仍是全部匹配数。自行调用本地 API 的工具需使用 `limit`/`offset` 翻页；非法参数返回 422。具体参数及上限见 [历史接口说明](history-pagination.md)。跨页期间新增或删除记录可能使 offset 位置变化。
- 古籍转录适用其独立来源许可；项目有权授权的自有代码和原创图标适用 MIT，第三方组件适用各自许可证，详见随附声明。

## Windows 安装前置条件

- Windows x64；沿用当前用户安装模式及应用标识 `cn.yijing.workbench`。
- 需要 Microsoft Edge WebView2 Evergreen Runtime。若尚未安装，默认安装流程需要联网下载 Microsoft 官方 bootstrapper。
- 沿用未签名安装包方案；Windows 可能显示未知发布者或 SmartScreen 提示。候选包实际签名状态、文件版本及 SHA-256 应在 Windows 构建后核对，本草稿不提供尚未生成的安装包或校验值。
- DeepSeek 不属于安装或离线使用的必需条件。

## 现有数据与升级注意事项

本次沿用既有应用数据目录和数据库结构；与 v3.2.2 源码相比，数据库迁移模块与旧库导入模块未变更。历史分页只改变查询方式，不删除或重写已保存的起卦结果、经文或排盘。正式升级前请先关闭应用并备份本机数据，保留备份到最终验收完成；不要为升级而手动删除数据库。

“旧版数据导入”仍只允许导入到空白桌面档案，不是向已有档案合并数据的功能。DPAPI 保护的密钥与 Windows 用户相关，跨用户复制数据不能视为密钥可用的保证。沿用数据目录及通过合成数据测试不等于已完成正式包升级验收。

Windows 3.3.0 自动候选流程见 [独立 RC 验收记录](windows-rc-3.3.0-acceptance.md)：构建工作流可以在隔离 GitHub Windows runner 生成安装包及哈希，不会自动公开发布；仍需要单独进行 Windows 真实账户升级、GUI、DPAPI 等人工验收。学习导读的内容批准标准另见 [审核门槛](learning-approval-policy.md)。

## 候选源码与构建证据的区分

2026-10-20 此前已有多轮 GitHub Actions Windows 2022 运行完成 Python/前端回归、打包和 SHA-256 候选产物上传；对应已留存记录见 [Windows RC 验收表](windows-rc-3.3.0-acceptance.md)。其 `source_sha` 多为 PR 临时合并提交，不代表当前 main 的同 SHA 正式发布产物。

现已加入从 `main` 的真实 `push` 提交构建新候选，以及打包后端 sidecar 的令牌鉴权、健康检查与合成历史冒烟。**新流程实际运行结果必须单独记录，不预先宣称通过**；即使自动 CI 通过，也不能取代 Windows 真实账户 GUI、WebView2、DPAPI、备份恢复和从 v3.2.2 升级的人工验收。

学习导读另可通过 `python scripts/prepare_learning_review.py --output review-packets` 生成 64 个独立 Markdown 审核包；已有的 4 个批准条目保持可见，其余 60 条不会因生成材料自动公开。
